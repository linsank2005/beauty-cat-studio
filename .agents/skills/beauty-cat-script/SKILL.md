# 口播编剧

先读项目 `docs/IP与风格规范.md`、`docs/learning-v2/参考机制复学.md` 和 [汗液视频复学与应用](../../../docs/learning-v2/汗液视频复学与应用.md)。现有 `episodes/DEMO/episode.json` 是主表格式示例，画风以已确认 3.0 范例为准。

## 编写

1. 提炼这一期唯一要讲清楚的问题和观众看完能得到的答案。主题尚含混时先提出可审阅的切入，不替用户臆定关键立场。
2. 拆成问题/处境 → 原因或推进 → 反差或纠偏 → 可理解的结尾。粉猫是慵懒、嘴硬、会吐槽的成年人；不写成萌宠卖萌或老师宣讲。
3. 涉及科学、医疗、数据等事实时查读一手来源，具体主张和链接写入主表 `sources`。参考视频只证明表达机制，不能直接当事实来源。纯虚构情境不伪装成实证结论。
4. 写完整自然口播，不只给提纲。短句、具体动词，允许一句对白或画面承担笑点；不要照搬参考作者的角色、桥段或句子。口语阅读一次，删掉书面连接词和空泛升华。
5. 每个可录单元建立 `N01…`，正文写 `text`，预计区间写 `estimated`。先按约每秒 4—5 个中文字估算，再给停顿、画面阅读和反应留空间；总长不超过 180 秒。此速率只用于计划，录音后重新对齐。
6. 每段带一个画面意图：直接解释 / 隐喻 / 反差 / 反应 / 回扣。画面和台词必须共同工作：隐喻不改变事实因果，反差不能被误读为事实，关键概念优先直接说明。
7. 与画面编排一起找出本段的主要行为、态度转折、包袱和需要阅读的关系；为绘出与结果反应留时间，但不为走完固定绘画步骤添加赘句。画面可承担细节，口播不逐项朗读所有上色/道具步骤。角色行为按内容决定，不为了复用抬爪素材把每期写成梳头。
8. 与画面编排职责来回修改同一份 `episode.json`；调整台词就同步版本、编号与相关事件，不能让分镜引用旧稿。

## 交付与边界

- 输出完整口播、必要来源、预计时长，并写入每期主表。
- 交给画面编排形成整体审阅包后再请用户确认；不把内部编稿完成当作用户审稿通过。
- 用户负责录音，不生成或借用声音替代用户录音。
- 缺信息只问实质影响内容的一个关键问题，同时继续已授权的独立工作；不另建多个 Agent。
