# 操作与主表

日常让 Codex 按项目 Skill 填写、检查和导出。只有一份作者主表，不需要维护几套提示词、口播和分镜。

## 文件放哪里

| 路径 | 用途 |
|---|---|
| `episodes/P001/episode.json` | 原口播、预计时间、画面事件和图层；唯一作者主表 |
| `episodes/P001/review/` | 审阅 HTML/Markdown、可录稿、关键 PNG、字幕 |
| `episodes/P001/episode.aligned.json` | 录音后的实际稿，保留预计字段 |
| `episodes/P001/alignment/` | 原始识别、差异报告、最新成功/失败状态 |
| `studio/public/ip/`、`props/` | 跨期猫猫与道具 |
| `studio/public/episodes/P001/` | 本期素材、录音副本和派生预览主表 |
| `exports/P001/` | MP4、SRT 和本次主表快照 |

`studio/public/episodes/active/episode.json` 只是最近审阅稿的预览副本，勿单独编辑。修订作者主表后重新生成 review。实际时间稿生成后，不要直接改作者主表而沿用旧对齐结果；程序会用哈希检查。

## 一份主表怎样关联

`narration` 使用稳定 `N01…`；`scenes` 使用 `S01…`；每个 `beat` 使用 `E01…` 并引用 `narrationId`。一个可录单元可以包含多个视觉事件。

```json
{
  "id": "E02", "narrationId": "N01", "at": 2.4,
  "anchor": "收拾", "action": "镜子与洗手台加入",
  "meaning": "说明本段发生在出门准备时", "method": "direct"
}
```

`at` 是预计秒数；录音后增加 `actualAt` 和 `actualMethod`。`anchor` 尽量用对应句里的独特词组。没匹配到关键词的事件会标记为句内估计，需看听复核。

图层的 `showAt` / `hideAt` 引用本场景事件编号，`x/y/width/height` 是 1920×1080 画布坐标。图层数组越靠后越在上层。

| 图层 | 常改字段 |
|---|---|
| `cat` | `view: sit/front/groom/walk`、`expression`、`revealSeconds`、`walk` 参数、大小位置 |
| `image` | `src` 相对 `studio/public/`，独立 PNG/SVG |
| `text` | `text`、`fontSize`、`color`；长中文用后期文字 |
| `path` | SVG `path`、颜色和线宽，`draw` 可渐进描边 |
| `shape` | `rect/ellipse`、填色、线宽、圆角 |

出现效果为 `draw / pop / wipe / fade / none`。`draw` 用于猫坐姿或 SVG path，`wipe` 用于 image，`pop/fade` 用于各类普通图层。`reactions` 引用事件切表情，`motion` 引用事件逐段移动；并非骨骼绑定。

## 在同一主表安排绘出与多个动作

按 [汗液视频复学与应用](learning-v2/汗液视频复学与应用.md) 编排：把主要对象的线稿、分区色面、必要细节、动作结果和反应写成多个 `beats`，阶段名及姿态来源写在 `action`，作用写在 `meaning`，每个阶段引用对应口播与锚点。沿用现有字段，不另维护阶段时间表。

姿态在 `layers` 中落实：已有 `cat.view` 仅接受上述四种；新姿态需真实素材与实现，可用独立 `image/path` 状态图层组织，不填不存在的 `view: drink/run`。坐姿与抬爪支持三种表情，正面与背身当前为固定脸。手持物与身体改变接触关系时用对应状态素材，不能只改 `motion` 或 `reactions`。

分镜审阅应同时显示主要姿态选择和代表性的线稿/部分填色/细节完成/表演结果。现有自动 review 的场景代表图不足时按事件另补状态图；未制作部分标为计划。录音后逐事件调整实际时刻，语速快时可合并次要上色步骤，保留动作结果与反应的可读时间。复杂图的分区绘出仍需实际图层或对应遮罩，不是主表写出阶段名称就自动具备。

以 [DEMO 主表](../episodes/DEMO/episode.json) 为可直接运行的完整例子。Studio 的普通参数入口只有主表文件、静音、字幕；场景图层和时间在 JSON 中修改。模板的时长、表情可在 `CatReveal` 参数中调整。不要承诺 JSON 映射的每个图层都可在 Studio 任意拖动并写回主表。

## 命令

```powershell
# 初始化空主表；不会自动生成口播
./Start-Cat.ps1 -Action init -Episode P001 -Topic '主题'
# 填完主表后，生成实际关键帧供用户一起审阅
./Start-Cat.ps1 -Action check -Episode P001
./Start-Cat.ps1 -Action review -Episode P001
# 获得用户审稿通过，改 status=approved，再处理真实录音
./Start-Cat.ps1 -Action align -Episode P001 -Audio 'E:\录音\P001.wav'
./Start-Cat.ps1 -Action review -Episode P001 -Actual -Overwrite
./Start-Cat.ps1 -Action check -Episode P001 -Actual
./Start-Cat.ps1 -Action render -Episode P001 -Actual
# 供用户后续剪辑：纯画面、无字幕，仍输出独立 SRT
./Start-Cat.ps1 -Action render -Episode P001 -Actual -Silent -Clean
# 看最近一期，或重导整套模板
./Start-Cat.ps1 -Action preview -Episode P001 -Actual
./Start-Cat.ps1 -Action templates -Overwrite
```

输出命名区分 `带口播` / `无声`，无烧录字幕版增加 `_无字幕`。程序默认拒绝覆盖 MP4/PNG；你已授权修订时加 `-Overwrite`。正常审阅由预计转实际时关键 PNG 路径相同，需显式覆盖。

## 对齐出现差异怎么办

先看 `alignment/alignment-report.json` 和实际说法。字幕沿用已审原文，ASR 的“窝/屋”错字不会自动改稿；真正改说要同步主表再对齐。漏句或低匹配率会退出，保存差异而不新建实际稿；最新一次失败也会阻止旧实际稿被当成新结果渲染。

确定只是识别错字时，Codex 可在保留原始识别的前提下制作校正识别文件，使用 `scripts/align_voice.py --asr-json <校正文件>` 重排。该文件必须匹配音频 SHA256，并保留实际时间；不要靠臆造时间“修正”漏录。

ASR 时间来自词，长词内部的字时刻采用均分估计。实际稿的 `alignmentReview=pending` 提醒听看复核，可对有偏差的句首句尾、关键词和视觉停留做局部校正。最终同步判断依靠真实录音播放，不用全片统一拉伸。

## 恢复环境与复现

工具路径在 `local.config.json`；共享 Whisper small 模型在项目外，本机已缓存。工程依赖在本地 `.venv/` 与 `studio/node_modules/`，Chrome 在 `studio/.remotion/`。所需运行环境已在本机就绪。

```powershell
./Start-Cat.ps1 -Action setup
./Start-Cat.ps1 -Action doctor
./Start-Cat.ps1 -Action check -Episode DEMO
./.venv/Scripts/python.exe scripts/verify_alignment.py
./.venv/Scripts/python.exe scripts/verify_delivery.py
```

`setup` 用锁定版本恢复依赖，缺 Chrome 时走 Remotion 官方下载。换电脑需先设置实际 Node、FFmpeg、Python 引导程序和已有模型路径；不会在项目里复制整个共享模型。复学/录音复现脚本需要原始 `study-video/`，源码归档不重复打包这些大文件。
